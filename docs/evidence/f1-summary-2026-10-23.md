# Conclusão sanitizada — F1 — 2026-10-23

**Baseline histórico:** NexusLab/NexusForever. Esta evidência registra uma
avaliação anterior e não representa o estado vigente do Projeto Aastra/AAEmu.

## Decisão

**FAIL (precondições não satisfeitas).** O inventário foi executado sem iniciar
ou encerrar serviços, mas o Gate F1 ainda não pode ser aprovado.

## Evidências positivas

- Git 2.55.0, .NET SDK 10.0.302 e PowerShell 5.1 observados.
- Os 12 ports candidatos estavam livres no instante da coleta.
- Clones rasos dos dois upstreams resolveram os commits do manifesto e ficaram
  em diretório ignorado.
- O índice Git não contém aliases de segredos, cliente, assets, dados, backup,
  telemetria ou evidência local; provas sintéticas de ignore passaram.
- Nenhum literal provável de segredo foi encontrado nos arquivos versionados;
  ocorrências foram apenas texto de política/ignore.

## Bloqueios

1. Docker não instalado/encontrado e containers Linux não comprovados.
2. WSL não instalado; hypervisor ausente e virtualização de firmware reportada
   como desabilitada. A leitura de Optional Features exigiu elevação.
3. Apenas 7,04 GiB livres em C:; capacidade exigida ainda não medida.
4. Visual Studio/MSBuild não encontrados no `PATH`; requisito do upstream não
   comprovado integralmente.
5. Cópia autorizada do cliente 16042 não localizada porque nenhum caminho foi
   autorizado para busca.
6. Política de forks, bindings e segredos aguarda aprovação da Spec 001.
7. O AppHost upstream usa `IPAddress.Any` para três listeners externos.

## Riscos registrados

- O commit candidato principal não é assinado e a branch upstream não é
  protegida; os três checks observados passaram.
- PR #570 altera setup, assets, conta, migrations e world data; exige revisão
  multidomínio antes de ser incorporado.
- O WorldDatabase declara origem parcial em sniffs do servidor retail; uso e
  distribuição precisam de revisão jurídica qualificada.
- Há caminho de erro no handshake do World que inclui e-mail e session key em
  texto de exceção; deve ser validado/corrigido antes de credenciais reais.

Detalhes locais sanitizados estão em `evidence/local/f1-inventory.yaml`.
